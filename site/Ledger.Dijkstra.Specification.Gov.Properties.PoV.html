    Properties of GOV: Preservation of Value¶

    This module proves the two governance-deposit accounting facts that the top-level preservation-of-value proof (LEDGER-pov in Ledger.Properties.PoV) assumes as module parameters:

    • rmOrphanDRepVotes-coinFromGovDeposit: rmOrphanDRepVotes only rewrites the gvDRep votes of each governance action, never GovActionState.deposit, so it leaves coinFromGovDeposit unchanged.

    • GOVS-coinFromGovDeposit: a GOVS step grows coinFromGovDeposit by exactly the govProposalsDeposits of the proposals in its signal list — GOV-Propose stores deposit = pp .govActionDeposit for the new action, and GOV-Vote never changes a deposit.

    Their statements match the corresponding LEDGER-PoV module parameters (modulo this module's own proposalsOf copy; see below).

    {-# OPTIONS --safe #-}

open import Ledger.Dijkstra.Specification.Transaction
open import Ledger.Dijkstra.Specification.Abstract

module Ledger.Dijkstra.Specification.Gov.Properties.PoV
  (txs : _) (open TransactionStructure txs)
  (abs : AbstractFunctions txs) (open AbstractFunctions abs)
  where

open import Data.Nat.Base using () renaming (_+_ to infixl 6 _+ᴺ_)
open import Data.Nat.Properties using (+-assoc; +-identityʳ)
open import Data.Nat.Tactic.RingSolver using (solve-∀)

open import Ledger.Prelude

open import Ledger.Dijkstra.Specification.Certs govStructure
open import Ledger.Dijkstra.Specification.Gov govStructure
open import Ledger.Dijkstra.Specification.Ledger txs abs
open import Ledger.Dijkstra.Specification.Utxo txs abs

open import Interface.STS

    proposalsOf¶

    The right injections of a list of sums, used (at GovVote ⊎ GovProposal) to extract the proposals from a mixed GOVS signal list. Ledger.Properties.PoV defines an identical function for stating its GOVS-coinFromGovDeposit parameter, but importing it here would create an import cycle once Ledger.Properties.PoV is rewired to import this module. So we keep a local copy (clause-for-clause identical), together with the proposalsOf-Proposals+Votes extraction lemma.

    proposalsOf : ∀ {A B : Type} → List (A ⊎ B) → List B
proposalsOf []            = []
proposalsOf (inj₁ _ ∷ xs) = proposalsOf xs
proposalsOf (inj₂ p ∷ xs) = p ∷ proposalsOf xs

    proposalsOf (GovProposals+Votes t) recovers exactly the proposals of t, since GovProposals+Votes lists all proposals (as right injections) before all votes (as left injections).

    proposalsOf-Proposals+Votes : ∀ {ℓ} (t : Tx ℓ)
  → proposalsOf (GovProposals+Votes t) ≡ ListOfGovProposalsOf t
proposalsOf-Proposals+Votes t = go (ListOfGovProposalsOf t) (ListOfGovVotesOf t)
  where
  drop-votes : ∀ {A B : Type} (vs : List A)
    → proposalsOf {A = A} {B = B} (map inj₁ vs) ≡ []
  drop-votes []       = refl
  drop-votes (_ ∷ vs) = drop-votes vs
  go : ∀ {A B : Type} (ps : List B) (vs : List A)
     → proposalsOf (map inj₂ ps ++ map inj₁ vs) ≡ ps
  go []       vs = drop-votes vs
  go (p ∷ ps) vs = cong (p ∷_) (go ps vs)

    Arithmetic helpers¶

    The two pure +-rearrangements below are discharged by the reflective ring solver (Data.Nat.Tactic.RingSolver), with the solver-facing statements written over the raw natural-number addition _+ᴺ_; see Ledger.Properties.PoV for the solver conventions and the reason the overloaded _+_ cannot appear in solver-facing statements.

    swap-head : ∀ a b c → a +ᴺ (b +ᴺ c) ≡ b +ᴺ (a +ᴺ c)
swap-head = solve-∀

rotate-in : ∀ a b c → a +ᴺ b +ᴺ c ≡ b +ᴺ (a +ᴺ c)
rotate-in = solve-∀

    rmOrphanDRepVotes preserves coinFromGovDeposit¶

    rmOrphanDRepVotes maps over the GovState, rewriting only the votes field of each GovActionState (it filters the gvDRep votes down to registered DReps). The record update leaves deposit definitionally unchanged in every cons cell, so a list induction closes the proof.

    rmOrphanDRepVotes-coinFromGovDeposit : ∀ (cs : CertState) (g : GovState)
  → coinFromGovDeposit (rmOrphanDRepVotes cs g) ≡ coinFromGovDeposit g
rmOrphanDRepVotes-coinFromGovDeposit cs []              = refl
rmOrphanDRepVotes-coinFromGovDeposit cs ((_ , gas) ∷ g) =
  cong (GovActionState.deposit gas +_) (rmOrphanDRepVotes-coinFromGovDeposit cs g)

    A cons law for govProposalsDeposits¶

    govProposalsDeposits is a foldl that adds the (constant) govActionDeposit to its accumulator once per proposal. The GOVS induction below consumes proposals head-first, so it needs the cons law: one proposal contributes one govActionDeposit. Since foldl buries the head's contribution in the accumulator, the workhorse is the accumulator-shift lemma govProposalsDeposits-acc; the cons law is its direct corollary. (The GOVS induction uses the shift lemma directly: the fold discards the list elements, so after reduction the head proposal never appears in the equation.)

    govProposalsDeposits-acc : ∀ (pp : PParams) (acc : Coin) (ps : List GovProposal)
  → foldl (λ a _ → a + PParams.govActionDeposit pp) acc ps
    ≡ acc + govProposalsDeposits pp ps
govProposalsDeposits-acc pp acc []       = sym (+-identityʳ acc)
govProposalsDeposits-acc pp acc (_ ∷ ps) =
  trans (govProposalsDeposits-acc pp (acc + d) ps)
        (trans (+-assoc acc d (govProposalsDeposits pp ps))
               (cong (acc +_) (sym (govProposalsDeposits-acc pp d ps))))
  where d = PParams.govActionDeposit pp

govProposalsDeposits-∷ : ∀ (pp : PParams) {p : GovProposal} (ps : List GovProposal)
  → govProposalsDeposits pp (p ∷ ps)
    ≡ PParams.govActionDeposit pp + govProposalsDeposits pp ps
govProposalsDeposits-∷ pp = govProposalsDeposits-acc pp (PParams.govActionDeposit pp)

    Per-step facts: addVote and insertGovAction¶

    A GOV-Vote step concludes in addVote, which maps over the state, rewriting only the votes field of the matching action. Whether or not an entry matches the voted action id, its deposit is untouched, so coinFromGovDeposit is preserved. (addVote is opaque, so the proof must unfold it explicitly.)

    opaque
  unfolding addVote

  addVote-coinFromGovDeposit :
    ∀ {s : GovState} {aid voter v}
    → coinFromGovDeposit (addVote s aid voter v) ≡ coinFromGovDeposit s
  addVote-coinFromGovDeposit {[]}                            = refl
  addVote-coinFromGovDeposit {(gid , gas) ∷ s} {aid} {voter} {v}
    with gid ≟ aid
  ... | yes _ = cong (GovActionState.deposit gas +_)
                     (addVote-coinFromGovDeposit {s} {aid} {voter} {v})
  ... | no  _ = cong (GovActionState.deposit gas +_)
                     (addVote-coinFromGovDeposit {s} {aid} {voter} {v})

    A GOV-Propose step concludes in addAction, which is insertGovAction of a fresh GovActionState pair carrying deposit = pp .govActionDeposit. insertGovAction is a priority-ordered insertion; wherever the new pair lands, coinFromGovDeposit grows by exactly its deposit. The proof is a list induction with a case split on the priority comparison: in the then branch the new pair sinks past the head, so the head's deposit and the inserted deposit swap places (swap-head); in the else branch the list is extended in place and both sides agree definitionally.

    insertGovAction-coinFromGovDeposit :
  ∀ {s : GovState} {p : GovActionID × GovActionState}
  → coinFromGovDeposit (insertGovAction s p)
    ≡ GovActionState.deposit (proj₂ p) + coinFromGovDeposit s
insertGovAction-coinFromGovDeposit {[]}                 {_}             = refl
insertGovAction-coinFromGovDeposit {(gaID₀ , gaSt₀) ∷ s} {gaID₁ , gaSt₁}
  with govActionPriority (GovActionTypeOf gaSt₀)
         ≤? govActionPriority (GovActionTypeOf gaSt₁)
... | yes _ =
  trans (cong (GovActionState.deposit gaSt₀ +_)
              (insertGovAction-coinFromGovDeposit {s} {gaID₁ , gaSt₁}))
        (swap-head (GovActionState.deposit gaSt₀)
                   (GovActionState.deposit gaSt₁)
                   (coinFromGovDeposit s))
... | no  _ = refl

    GOVS accounting¶

    GOVS is the indexed reflexive-transitive closure of GOV: the convenience wrapper fixes the index at 0, but BS-ind's tail runs at suc n, so the induction must be stated over the primed relation _⊢_⇀⟦_⟧ᵢ*'_, generalized over the environment-index pair, and then specialized to 0. Per step, GOV-Vote preserves the deposit total (addVote-coinFromGovDeposit, and its signal contributes no proposal), while GOV-Propose adds one govActionDeposit on both sides (insertGovAction-coinFromGovDeposit on the state side, govProposalsDeposits-∷ on the accounting side).

    GOVSᵢ-coinFromGovDeposit :
  ∀ {Γ : GovEnv} {n : ℕ} {s s' : GovState} {sigs : List (GovVote ⊎ GovProposal)}
  → _⊢_⇀⟦_⟧ᵢ*'_ {_⊢_⇀⟦_⟧ᵇ_ = IdSTS} {_⊢_⇀⦇_,GOV⦈_} (Γ , n) s sigs s'
  → coinFromGovDeposit s'
    ≡ coinFromGovDeposit s + govProposalsDeposits (PParamsOf Γ) (proposalsOf sigs)

GOVSᵢ-coinFromGovDeposit (BS-base Id-nop) = sym (+-identityʳ _)

GOVSᵢ-coinFromGovDeposit {Γ} (BS-ind {sigs = sigs} (GOV-Vote _) rest) =
  trans (GOVSᵢ-coinFromGovDeposit rest)
        (cong (_+ govProposalsDeposits (PParamsOf Γ) (proposalsOf sigs))
              addVote-coinFromGovDeposit)

GOVSᵢ-coinFromGovDeposit {Γ} {s = s} (BS-ind {sigs = sigs} (GOV-Propose _) rest) =
  trans (GOVSᵢ-coinFromGovDeposit rest)
  (trans (cong (_+ X) (insertGovAction-coinFromGovDeposit {s = s}))
  (trans (rotate-in dep (coinFromGovDeposit s) X)
         (cong (coinFromGovDeposit s +_)
               (sym (govProposalsDeposits-acc (PParamsOf Γ) dep (proposalsOf sigs))))))
  where
  X   = govProposalsDeposits (PParamsOf Γ) (proposalsOf sigs)
  dep = PParams.govActionDeposit (PParamsOf Γ)

    Specializing to index 0 gives the statement in the shape of the LEDGER-PoV module parameter:

    GOVS-coinFromGovDeposit :
  ∀ {Γ : GovEnv} {govSt govSt′ : GovState} {props : List (GovVote ⊎ GovProposal)}
  → Γ ⊢ govSt ⇀⦇ props ,GOVS⦈ govSt′
  → coinFromGovDeposit govSt′
    ≡ coinFromGovDeposit govSt + govProposalsDeposits (PParamsOf Γ) (proposalsOf props)
GOVS-coinFromGovDeposit = GOVSᵢ-coinFromGovDeposit
