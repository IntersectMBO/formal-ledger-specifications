    Blockchain Layer¶

    The chain layer applies one block at a time. A block without a certificate ticks the new-epoch state to its slot and runs its body on the ticked state. A block whose body certifies the endorser block (EB) announced by its predecessor first applies that EB's closure to the ledger state the predecessor left, in the predecessor's environment, and only then ticks and runs its own body (Step 5; Ledger Management).

    Definition of ChainState¶

    Beside the NewEpochState, the ChainState records the last applied block: its slot, the hash of its header, and the EB its header announced, if any. Every block replaces this record, so an announcement survives exactly one block and only the immediate successor can certify it (Step 5). (The consensus specification's record of the same name carries the block number, the slot, and the header hash.)

    record LastAppliedBlock : Type where
  field
    slot         : Slot
    headerHash   : RBHeaderHash
    announcedEB  : Maybe Announcement

record ChainState : Type where
  field
    newEpochState  : NewEpochState
    lastApplied    : Maybe LastAppliedBlock

    instance
  unquoteDecl HasCast-LastAppliedBlock = derive-HasCast
    [ (quote LastAppliedBlock , HasCast-LastAppliedBlock) ]

  HasNewEpochState-ChainState : HasNewEpochState ChainState
  HasNewEpochState-ChainState .NewEpochStateOf = ChainState.newEpochState

  HasLastEpoch-ChainState : HasLastEpoch ChainState
  HasLastEpoch-ChainState .LastEpochOf = LastEpochOf ∘ NewEpochStateOf

  HasEpochState-ChainState : HasEpochState ChainState
  HasEpochState-ChainState .EpochStateOf = EpochStateOf ∘ NewEpochStateOf

  HasEnactState-ChainState : HasEnactState ChainState
  HasEnactState-ChainState .EnactStateOf = EnactStateOf ∘ EpochStateOf

  HasLedgerState-ChainState : HasLedgerState ChainState
  HasLedgerState-ChainState .LedgerStateOf = LedgerStateOf ∘ EpochStateOf

  HasUTxOState-ChainState : HasUTxOState ChainState
  HasUTxOState-ChainState .UTxOStateOf = UTxOStateOf ∘ LedgerStateOf

  HasPParams-ChainState .PParamsOf = PParamsOf ∘ EnactStateOf

    Resolved endorser blocks¶

    The block carries its certificate alone. The EB it certifies and that EB's closure, its referenced transactions resolved and in reference order, reach the chain rule beside the block. The rules take the closure as an input.

    record ResolvedEB : Type where
  field
    eb       : EndorserBlock
    closure  : List TopLevelTx

pendingEB : LastAppliedBlock → Maybe EBHash
pendingEB la = proj₁ <$> LastAppliedBlock.announcedEB la

announcingEnv : ChainState → LastAppliedBlock → LedgerEnv
announcingEnv cs la =
  $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.Chain.html#2621}{\htmlId{4682}{\htmlClass{Field}{\text{LastAppliedBlock.slot}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#4673}{\htmlId{4704}{\htmlClass{Bound}{\text{la}}}}\, \\ \,\href{Ledger.Prelude.html#2367}{\htmlId{4709}{\htmlClass{Function Operator}{\text{∣}}}}\, \,\href{Ledger.Dijkstra.Specification.Enact.html#926}{\htmlId{4711}{\htmlClass{Function}{\text{constitution}}}}\, \,\href{Ledger.Prelude.html#2367}{\htmlId{4724}{\htmlClass{Function Operator}{\text{∣}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.PParams.html#8103}{\htmlId{4728}{\htmlClass{Field}{\text{PParamsOf}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#4670}{\htmlId{4738}{\htmlClass{Bound}{\text{cs}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#4794}{\htmlId{4743}{\htmlClass{Function}{\text{es}}}}\, \\ \,\href{Ledger.Prelude.Base.html#1263}{\htmlId{4748}{\htmlClass{Field}{\text{TreasuryOf}}}}\, \,\htmlId{4759}{\htmlClass{Symbol}{\text{(}}}\,\,\href{Ledger.Dijkstra.Specification.Epoch.html#5450}{\htmlId{4760}{\htmlClass{Field}{\text{NewEpochStateOf}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#4670}{\htmlId{4776}{\htmlClass{Bound}{\text{cs}}}}\,\,\htmlId{4778}{\htmlClass{Symbol}{\text{)}}}\, \end{pmatrix}$
  where
    es = EnactStateOf cs
    open EnactState es using (constitution)

    pendingEB reads the announced hash; the declared size beside it is no validity condition (see BlockBody). announcingEnv uses the announcing slot and the enact state, parameters, and treasury before the tick.

    The CHAIN Transition System¶

    CHAIN-None handles a block without a certificate or a resolved EB. It ticks and runs BBODY. CHAIN-EB checks the certificate in the chain context, applies the EB at the announcing slot, and then ticks and runs the body. Certificate checking is read-only; the EB premise produces the ledger state the tick continues from.

    The contextual checks require the previous block to have announced the EB, the certification delay to have elapsed, the two blocks to share an epoch, and ValidEBCert to hold for the announcing header's hash and that epoch's committee and threshold (Step 5; Certificate Validation). The same-epoch premise also rules out certification across an era boundary, since era transitions occur at epoch boundaries. It costs at most one EB per boundary.

    The EB premise states full declarative validity and application (see Leios.Validity). An implementation may avoid repeating validation when reapplying a certified closure; agreement with this full-rule relation is a separate proof obligation. A certifying block carries no transactions of its own, by ValidLeiosBlock.

    data _⊢_⇀⦇_,CHAIN⦈_ : ⊤ → ChainState → Block × Maybe ResolvedEB → ChainState → Type where

  CHAIN-None : ∀ {bcur'} {b : Block} {nes : NewEpochState} {cs : ChainState}

        → let open ChainState cs; open Block b; open BHeader bheader
          open BHBody bhbody; open NewEpochState nes; open EpochState epochState
      in

        let cs' = record cs
                { newEpochState = record nes
                    { bcur = bcur'; epochState = record (EpochStateOf nes) {ls = ls'} }
                ; lastApplied = just $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1792}{\htmlId{7061}{\htmlClass{Function}{\text{slot}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#2467}{\htmlId{7068}{\htmlClass{Function}{\text{bHeaderHash}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1864}{\htmlId{7082}{\htmlClass{Function}{\text{announcedEB}}}}\, \end{pmatrix}$ }
    in
    ∙ ebCert ≡ nothing
    ∙ tt ⊢ newEpochState ⇀⦇ slot ,TICK⦈ nes
    ∙ (es , acnt) ⊢ (ls , bcur) ⇀⦇ b ,BBODY⦈ (ls' , bcur')
      ────────────────────────────────
      _ ⊢ cs ⇀⦇ (b , nothing) ,CHAIN⦈ cs'

  CHAIN-EB : ∀ {bcur'} {b : Block} {reb : ResolvedEB} {cert : EBCert}
               {la : LastAppliedBlock} {nes : NewEpochState} {cs : ChainState}
               {ls₁ : LedgerState}

        → let open ChainState cs; open Block b; open BHeader bheader
          open BHBody bhbody; open NewEpochState nes; open EpochState epochState
          open LastAppliedBlock la using (headerHash) renaming (slot to announcingSlot)
          open ResolvedEB reb
      in

        let pp    = PParamsOf cs
        cmt   = NewEpochState.leiosCommittee newEpochState
        nes₁  = record newEpochState { epochState = record (EpochStateOf cs) {ls = ls₁} }
        cs'   = record cs
                  { newEpochState = record nes
                      { bcur = bcur'; epochState = record (EpochStateOf nes) {ls = ls'} }
                  ; lastApplied = just $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1792}{\htmlId{8187}{\htmlClass{Function}{\text{slot}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#2467}{\htmlId{8194}{\htmlClass{Function}{\text{bHeaderHash}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1864}{\htmlId{8208}{\htmlClass{Function}{\text{announcedEB}}}}\, \end{pmatrix}$ }
    in
    ∙ ebCert ≡ just cert
    ∙ lastApplied ≡ just la
    ∙ pendingEB la ≡ just (hashEB eb)
    ∙ announcingSlot + certificationDelay pp ≤ slot
    ∙ epoch announcingSlot ≡ epoch slot
    ∙ ValidEBCert cmt (PParams.leiosQuorumStakeThreshold pp) (rbHeaderHashBytes headerHash) cert
    ∙ (announcingEnv cs la , closure) ⊢ LedgerStateOf cs ⇀⦇ eb ,EB⦈ ls₁
    ∙ tt ⊢ nes₁ ⇀⦇ slot ,TICK⦈ nes
    ∙ (es , acnt) ⊢ (ls , bcur) ⇀⦇ b ,BBODY⦈ (ls' , bcur')
      ────────────────────────────────
      _ ⊢ cs ⇀⦇ (b , just reb) ,CHAIN⦈ cs'

    A certificate without its resolved EB, or a resolved EB beside a block that carries no certificate, admits no transition. Every successful block replaces lastApplied, retiring the previous announcement and recording its own announcement, if any, for its successor.
