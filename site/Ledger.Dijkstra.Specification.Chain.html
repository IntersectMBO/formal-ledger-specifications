    Blockchain Layer¶

    The chain layer applies one block at a time. A block without a certificate ticks the new-epoch state to its slot and runs its body on the ticked state. A block whose body certifies the endorser block (EB) announced by its predecessor first applies that EB's closure to the ledger state the predecessor left, in the predecessor's environment, and only then ticks and runs its own body (Step 5; Ledger Management).

    Definition of ChainState¶

    Beside the NewEpochState, the ChainState records the last applied block: its slot, the hash of its header, and the EB its header announced, if any. Every block replaces this record, so an announcement survives exactly one block and only the immediate successor can certify it (Step 5). (The consensus specification's record of the same name carries the same three fields beside the block number.)

    record LastAppliedBlock : Type where
  field
    slot         : Slot
    headerHash   : RBHeaderHash
    announcedEB  : Maybe Announcement

record ChainState : Type where
  field
    newEpochState  : NewEpochState
    lastApplied    : Maybe LastAppliedBlock

    instance
  unquoteDecl HasCast-LastAppliedBlock = derive-HasCast
    [ (quote LastAppliedBlock , HasCast-LastAppliedBlock) ]

  HasNewEpochState-ChainState : HasNewEpochState ChainState
  HasNewEpochState-ChainState .NewEpochStateOf = ChainState.newEpochState

  HasLastEpoch-ChainState : HasLastEpoch ChainState
  HasLastEpoch-ChainState .LastEpochOf = LastEpochOf ∘ NewEpochStateOf

  HasEpochState-ChainState : HasEpochState ChainState
  HasEpochState-ChainState .EpochStateOf = EpochStateOf ∘ NewEpochStateOf

  HasEnactState-ChainState : HasEnactState ChainState
  HasEnactState-ChainState .EnactStateOf = EnactStateOf ∘ EpochStateOf

  HasLedgerState-ChainState : HasLedgerState ChainState
  HasLedgerState-ChainState .LedgerStateOf = LedgerStateOf ∘ EpochStateOf

  HasUTxOState-ChainState : HasUTxOState ChainState
  HasUTxOState-ChainState .UTxOStateOf = UTxOStateOf ∘ LedgerStateOf

  HasCertState-ChainState : HasCertState ChainState
  HasCertState-ChainState .CertStateOf = CertStateOf ∘ LedgerStateOf

  HasRewards-ChainState : HasRewards ChainState
  HasRewards-ChainState .RewardsOf = RewardsOf ∘ CertStateOf

  HasPParams-ChainState : HasPParams ChainState
  HasPParams-ChainState .PParamsOf = PParamsOf ∘ EnactStateOf

    The CERTIFY Transition System¶

    The certificate branch judges a block's certificate, when the block carries one, in the world of the block that announced the EB. That world is the chain state before the tick: its enact state and treasury are those the announcing block's own body ran under, and its committee is the announcing epoch's. The branch's environment packs what it reads from there, and certifyEnv reads it off the chain state.

    record CertifyEnv : Type where
  field
    lastApplied  : Maybe LastAppliedBlock
    committee    : LeiosCommittee
    enactState   : EnactState
    treasury     : Treasury

    instance
  unquoteDecl HasCast-CertifyEnv = derive-HasCast
    [ (quote CertifyEnv , HasCast-CertifyEnv) ]

certifyEnv cs = $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.Chain.html#2800}{\htmlId{5194}{\htmlClass{Field}{\text{lastApplied}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Epoch.html#4649}{\htmlId{5208}{\htmlClass{Function}{\text{leiosCommittee}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Enact.html#1180}{\htmlId{5225}{\htmlClass{Field}{\text{EnactStateOf}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#5187}{\htmlId{5238}{\htmlClass{Bound}{\text{cs}}}}\, \\ \,\href{Ledger.Prelude.Base.html#1263}{\htmlId{5243}{\htmlClass{Field}{\text{TreasuryOf}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#2765}{\htmlId{5254}{\htmlClass{Field}{\text{newEpochState}}}}\, \end{pmatrix}$

pendingEB : LastAppliedBlock → Maybe EBHash
pendingEB la = proj₁ <$> LastAppliedBlock.announcedEB la

    pendingEB is the hash of the EB the last applied block announced, if it announced one; the declared size beside it is no validity condition (see Leios.Types).

    The block carries its certificate alone. The EB it certifies and that EB's closure, its referenced transactions resolved and in reference order, reach the chain rule beside the block; the rules take the closure as an input and never ask whether data is available.

    record ResolvedEB : Type where
  field
    eb       : EndorserBlock
    closure  : List TopLevelTx

    Without a certificate, and with no resolved EB beside the block, the ledger state is unchanged. With both, the block certifies the EB its predecessor announced, and the branch requires the following, all in the announcing block's world:

    • the chain has a last applied block, and the EB it announced is the certified one (Step 5, rule 1);
    • the certificate is valid for the announcing block's header hash, against the committee and the quorum threshold of the announcing epoch (ValidEBCert; Certificate Validation, whose fifth check, that the message is the announcing header's hash taken from the chain context, is met by the message supplied here);
    • the EB is valid in the announcing block's environment, which is what the voters checked (ValidEB);
    • the closure applies through LEDGERS to the ledger state the announcing block left, and the resulting state is the one the chain rule continues from (Ledger Management).

    A certificate without its resolved EB, or a resolved EB beside a block that carries no certificate, admits no transition.

    data _⊢_⇀⦇_,CERTIFY⦈_ : CertifyEnv → LedgerState → Maybe EBCert × Maybe ResolvedEB → LedgerState → Type where

  CERTIFY-None : ∀ {Γ : CertifyEnv} {ls : LedgerState} →
      ────────────────────────────────
      Γ ⊢ ls ⇀⦇ (nothing , nothing) ,CERTIFY⦈ ls

  CERTIFY-EB : ∀ {Γ : CertifyEnv} {ls ls₁ : LedgerState} {cert : EBCert} {reb : ResolvedEB} {la : LastAppliedBlock}

        → let open CertifyEnv Γ; open ResolvedEB reb
          open LastAppliedBlock la renaming (slot to announcingSlot)
          open EnactState enactState using (constitution)
          open PParams (PParamsOf enactState) using (leiosQuorumStakeThreshold) in

        let  pp  = PParamsOf enactState
         Γ'  = $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.Chain.html#7706}{\htmlId{7933}{\htmlClass{Field}{\text{announcingSlot}}}}\, \\ \,\href{Ledger.Prelude.html#2367}{\htmlId{7950}{\htmlClass{Function Operator}{\text{∣}}}}\, \,\href{Ledger.Dijkstra.Specification.Enact.html#926}{\htmlId{7952}{\htmlClass{Function}{\text{constitution}}}}\, \,\href{Ledger.Prelude.html#2367}{\htmlId{7965}{\htmlClass{Function Operator}{\text{∣}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#7889}{\htmlId{7969}{\htmlClass{Bound}{\text{pp}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#4943}{\htmlId{7974}{\htmlClass{Function}{\text{enactState}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#4973}{\htmlId{7987}{\htmlClass{Function}{\text{treasury}}}}\, \end{pmatrix}$
    in
    ∙ lastApplied ≡ just la
    ∙ pendingEB la ≡ just (hashEB eb)
    ∙ ValidEBCert committee leiosQuorumStakeThreshold (rbHeaderHashBytes headerHash) cert
    ∙ ValidEB {Γ'} {ls} eb closure
    ∙ Γ' ⊢ ls ⇀⦇ closure ,LEDGERS⦈ ls₁
      ────────────────────────────────
      Γ ⊢ ls ⇀⦇ (just cert , just reb) ,CERTIFY⦈ ls₁

    Two decisions fix the world the branch reads, and both follow from one principle: a certificate proves what the voters checked, and the voters could check only the announcing block's world.

    • The committee is the one in the chain state before the tick, the committee of the announcing block's epoch, which also sizes the certificate's signer bitfield. Reading it there needs no new state.
    • The quorum threshold is the announcing block's as well, read from the same enact state.

    The certification delay is not a premise of the branch. It compares two slots under the parameters in force at the certifying block, and the chain rule checks it after the tick, below. A certificate that fails a check admits no transition, like every other block fault; the Computational instance names the failed premise.

    The CHAIN Transition System¶

    The chain rule's signal is the block together with the resolved EB it certifies, if it carries a certificate. The rule applies a block in three steps. The certificate branch takes the ledger state the last applied block left to ls₁; the new-epoch state with that ledger state ticks to the block's slot, so an epoch boundary between the two blocks sees the closure's effects in its reward update, ratification, and snapshots, though not in enactment, which installs what the previous boundary ratified; and the block's body runs on the ticked state, under the reference-script bound as before. A certifying block carries no transactions of its own, by ValidLeiosBlock, so its body contributes the bookkeeping alone.

    Between the tick and the body, the rule checks the certification delay: a certifying block's slot is at least certificationDelay slots after the announcing block's (Step 5, rule 3), with the parameters in force at the certifying block's own slot, those the tick installed. The consensus specification's header rule reads the same parameters, so the two specifications agree to the slot. delayChecks states the check by cases: a block without a certificate owes nothing, a certificate with no last applied block has nothing to certify, and otherwise the slots compare.

    delayChecks : PParams → Maybe LastAppliedBlock → Maybe EBCert → Slot → Type
delayChecks _  _         nothing   _ = ⊤
delayChecks _  nothing   (just _)  _ = ⊥
delayChecks pp (just la) (just _)  s = LastAppliedBlock.slot la + certificationDelay pp ≤ s

    delayChecks? : ∀ pp m c s → Dec (delayChecks pp m c s)
delayChecks? _  _         nothing  _ = yes tt
delayChecks? _  nothing   (just _) _ = no λ ()
delayChecks? pp (just la) (just _) s = ¿ LastAppliedBlock.slot la + certificationDelay pp ≤ s ¿

instance
  Dec-delayChecks : ∀ {pp m c s} → delayChecks pp m c s ⁇
  Dec-delayChecks {pp} {m} {c} {s} = ⁇ (delayChecks? pp m c s)

    data _⊢_⇀⦇_,CHAIN⦈_ : ⊤ → ChainState → Block × Maybe ResolvedEB → ChainState → Type where

  CHAIN : ∀ {bcur'} {b : Block} {reb : Maybe ResolvedEB} {nes : NewEpochState} {cs : ChainState} {ls₁ : LedgerState}

        → let open ChainState cs; open Block b; open BHeader bheader
          open BHBody bhbody; open NewEpochState nes
          open EpochState epochState; open EnactState es renaming (pparams to pp)
          open PParams ∣ pp ∣ using (maxRefScriptSizePerBlock) in

        let  nes₁  = record newEpochState { epochState = record (EpochStateOf cs) {ls = ls₁} }
         cs'   = record cs
                   { newEpochState  = record nes { bcur = bcur'; epochState = record epochState {ls = ls'} }
                   ; lastApplied    = just $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1732}{\htmlId{12092}{\htmlClass{Function}{\text{slot}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#2407}{\htmlId{12099}{\htmlClass{Function}{\text{bHeaderHash}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1804}{\htmlId{12113}{\htmlClass{Function}{\text{announcedEB}}}}\, \end{pmatrix}$
                   }
    in
    ∙ certifyEnv cs ⊢ LedgerStateOf cs ⇀⦇ (ebCert , reb) ,CERTIFY⦈ ls₁
    ∙ tt ⊢ nes₁ ⇀⦇ slot ,TICK⦈ nes
    ∙ delayChecks (PParamsOf es) lastApplied ebCert slot
    ∙ totalRefScriptsSize ls ts ≤ maxRefScriptSizePerBlock
    ∙ (es , acnt) ⊢ (ls , bcur) ⇀⦇ b ,BBODY⦈ (ls' , bcur')
      ────────────────────────────────
      _ ⊢ cs ⇀⦇ (b , reb) ,CHAIN⦈ cs'

    The resulting chain state records the block as the last applied block, with its announcement, if any, pending for its successor.
