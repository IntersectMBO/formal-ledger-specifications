    Blockchain Layer¶

    The chain layer applies one block at a time. A block without a certificate ticks the new-epoch state to its slot and runs its body on the ticked state. A block whose body certifies the endorser block (EB) announced by its predecessor first applies that EB's closure to the ledger state the predecessor left, in the predecessor's environment, and only then ticks and runs its own body (Step 5; Ledger Management).

    Definition of ChainState¶

    Beside the NewEpochState, the ChainState records the last applied block: its slot, the hash of its header, and the EB its header announced, if any. Every block replaces this record, so an announcement survives exactly one block and only the immediate successor can certify it (Step 5). (The consensus specification's record of the same name carries the block number, the slot, and the header hash.)

    record LastAppliedBlock : Type where
  field
    slot         : Slot
    headerHash   : RBHeaderHash
    announcedEB  : Maybe Announcement

record ChainState : Type where
  field
    newEpochState  : NewEpochState
    lastApplied    : Maybe LastAppliedBlock

    instance
  unquoteDecl HasCast-LastAppliedBlock = derive-HasCast
    [ (quote LastAppliedBlock , HasCast-LastAppliedBlock) ]

  HasNewEpochState-ChainState : HasNewEpochState ChainState
  HasNewEpochState-ChainState .NewEpochStateOf = ChainState.newEpochState

  HasLastEpoch-ChainState : HasLastEpoch ChainState
  HasLastEpoch-ChainState .LastEpochOf = LastEpochOf ∘ NewEpochStateOf

  HasEpochState-ChainState : HasEpochState ChainState
  HasEpochState-ChainState .EpochStateOf = EpochStateOf ∘ NewEpochStateOf

  HasEnactState-ChainState : HasEnactState ChainState
  HasEnactState-ChainState .EnactStateOf = EnactStateOf ∘ EpochStateOf

  HasLedgerState-ChainState : HasLedgerState ChainState
  HasLedgerState-ChainState .LedgerStateOf = LedgerStateOf ∘ EpochStateOf

  HasUTxOState-ChainState : HasUTxOState ChainState
  HasUTxOState-ChainState .UTxOStateOf = UTxOStateOf ∘ LedgerStateOf

  HasCertState-ChainState : HasCertState ChainState
  HasCertState-ChainState .CertStateOf = CertStateOf ∘ LedgerStateOf

  HasRewards-ChainState : HasRewards ChainState
  HasRewards-ChainState .RewardsOf = RewardsOf ∘ CertStateOf

  HasPParams-ChainState : HasPParams ChainState
  HasPParams-ChainState .PParamsOf = PParamsOf ∘ EnactStateOf

private variable
  ls' : LedgerState

    The CERTIFY Transition System¶

    The certificate branch judges a block's certificate, when the block carries one, in the world of the block that announced the EB. That world is the chain state before the tick: its enact state and treasury are those the announcing block's own body ran under, and its committee is the announcing epoch's. The branch's environment packs what it reads from there beside the certifying block's slot, and certifyEnv reads it off the chain state.

    record CertifyEnv : Type where
  field
    slot         : Slot
    lastApplied  : Maybe LastAppliedBlock
    committee    : LeiosCommittee
    enactState   : EnactState
    treasury     : Treasury

    instance
  unquoteDecl HasCast-CertifyEnv = derive-HasCast
    [ (quote CertifyEnv , HasCast-CertifyEnv) ]

certifyEnv cs s = $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.Chain.html#5171}{\htmlId{5177}{\htmlClass{Bound}{\text{s}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#2860}{\htmlId{5181}{\htmlClass{Function}{\text{lastApplied}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Epoch.html#4649}{\htmlId{5195}{\htmlClass{Function}{\text{leiosCommittee}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Enact.html#1180}{\htmlId{5212}{\htmlClass{Field}{\text{EnactStateOf}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#5168}{\htmlId{5225}{\htmlClass{Bound}{\text{cs}}}}\, \\ \,\href{Ledger.Prelude.Base.html#1263}{\htmlId{5230}{\htmlClass{Field}{\text{TreasuryOf}}}}\, \,\href{Ledger.Dijkstra.Specification.Chain.html#2825}{\htmlId{5241}{\htmlClass{Function}{\text{newEpochState}}}}\, \end{pmatrix}$

pendingEB : LastAppliedBlock → Maybe EBHash
pendingEB la = proj₁ <$> LastAppliedBlock.announcedEB la

    pendingEB is the hash of the EB the last applied block announced, if it announced one; the declared size beside it is no validity condition (see BlockBody).

    The block carries its certificate alone. The EB it certifies and that EB's closure, its referenced transactions resolved and in reference order, reach the chain rule beside the block; the rules take the closure as an input and never ask whether data is available.

    record ResolvedEB : Type where
  field
    eb       : EndorserBlock
    closure  : List TopLevelTx

    Without a certificate, and with no resolved EB beside the block, the ledger state is unchanged. With both, the block certifies the EB its predecessor announced, and the branch requires the following, all in the announcing block's world:

    • the chain has a last applied block, and the EB it announced is the certified one (Step 5, rule 1);
    • the certifying block's slot is at least certificationDelay slots after the announcing block's (Step 5, rule 3);
    • the two blocks share an epoch, so an announcement does not survive an epoch boundary and the first block of an epoch never certifies;
    • the certificate is valid for the announcing block's header hash, against the committee and the quorum threshold of the announcing epoch (ValidEBCert; Certificate Validation, whose fifth check, that the message is the announcing header's hash taken from the chain context, is met by the message supplied here);
    • the EB is valid in the announcing block's environment, which is what the voters checked (ValidEB);
    • the closure applies through LEDGERS, within the endorser block's limits on reference-script size and execution units, to the ledger state the announcing block left, and the resulting state is the one the chain rule continues from (Ledger Management).

    A certificate without its resolved EB, or a resolved EB beside a block that carries no certificate, admits no transition.

    data _⊢_⇀⦇_,CERTIFY⦈_ : CertifyEnv → LedgerState → Maybe EBCert × Maybe ResolvedEB → LedgerState → Type where

  CERTIFY-None : ∀ {Γ : CertifyEnv} {ls : LedgerState} →
      ────────────────────────────────
      Γ ⊢ ls ⇀⦇ (nothing , nothing) ,CERTIFY⦈ ls

  CERTIFY-EB : ∀ {Γ : CertifyEnv} {ls ls₁ : LedgerState} {cert : EBCert} {reb : ResolvedEB} {la : LastAppliedBlock}

        → let open CertifyEnv Γ; open ResolvedEB reb
          open LastAppliedBlock la renaming (slot to announcingSlot)
          open EnactState enactState using (constitution)
          open PParams (PParamsOf enactState)
            using (leiosQuorumStakeThreshold; leiosMaxRefScriptSizePerEB; leiosMaxEBExUnits) in

        let  pp   = PParamsOf enactState
         Γ'   = $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.Chain.html#8064}{\htmlId{8352}{\htmlClass{Field}{\text{announcingSlot}}}}\, \\ \,\href{Ledger.Prelude.html#2367}{\htmlId{8369}{\htmlClass{Function Operator}{\text{∣}}}}\, \,\href{Ledger.Dijkstra.Specification.Enact.html#926}{\htmlId{8371}{\htmlClass{Function}{\text{constitution}}}}\, \,\href{Ledger.Prelude.html#2367}{\htmlId{8384}{\htmlClass{Function Operator}{\text{∣}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#8306}{\htmlId{8388}{\htmlClass{Bound}{\text{pp}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#4917}{\htmlId{8393}{\htmlClass{Function}{\text{enactState}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.Chain.html#4947}{\htmlId{8406}{\htmlClass{Function}{\text{treasury}}}}\, \end{pmatrix}$
         Γeb  = $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.Chain.html#8343}{\htmlId{8435}{\htmlClass{Bound}{\text{Γ'}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.PParams.html#3393}{\htmlId{8440}{\htmlClass{Function}{\text{leiosMaxRefScriptSizePerEB}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.PParams.html#3349}{\htmlId{8469}{\htmlClass{Function}{\text{leiosMaxEBExUnits}}}}\, \end{pmatrix}$
    in
    ∙ lastApplied ≡ just la
    ∙ pendingEB la ≡ just (hashEB eb)
    ∙ announcingSlot + certificationDelay pp ≤ slot
    ∙ epoch announcingSlot ≡ epoch slot
    ∙ ValidEBCert committee leiosQuorumStakeThreshold (rbHeaderHashBytes headerHash) cert
    ∙ ValidEB {Γ'} {ls} eb closure
    ∙ Γeb ⊢ ls ⇀⦇ closure ,LEDGERS⦈ ls₁
      ────────────────────────────────
      Γ ⊢ ls ⇀⦇ (just cert , just reb) ,CERTIFY⦈ ls₁

    The epoch premise buys simplicity rather than safety. An epoch boundary already concentrates a great deal of work, and an announcement that outlived it would be one more thing to carry across; across an era boundary, the announcement, the certificate, and the endorser block would further have to stay syntactically compatible with the very format change a new era exists to make. Era transitions fall on epoch boundaries, so this one premise covers both, at a cost of at most one endorser block per boundary.

    It also makes the world the branch reads unambiguous. A certificate proves what the voters checked, and the voters could check only the announcing block's world; with no epoch boundary between the two blocks, that world's committee, quorum threshold, and parameters are also the certifying block's. The branch reads them from the chain state before the tick, where the committee is the announcing epoch's, which also sizes the certificate's signer bitfield.

    A certificate that fails a check admits no transition, like every other block fault; the Computational instance names the failed premise.

    The CHAIN Transition System¶

    The chain rule's signal is the block together with the resolved EB it certifies, if it carries a certificate. The rule applies a block in three steps. The certificate branch takes the ledger state the last applied block left to ls₁; the new-epoch state with that ledger state ticks to the block's slot; and the block's body runs on the ticked state. A certifying block carries no transactions of its own, by ValidLeiosBlock, so its body contributes the bookkeeping alone.

    data _⊢_⇀⦇_,CHAIN⦈_ : ⊤ → ChainState → Block × Maybe ResolvedEB → ChainState → Type where

  CHAIN : ∀ {bcur'} {b : Block} {reb : Maybe ResolvedEB} {nes : NewEpochState} {cs : ChainState} {ls₁ : LedgerState}

        → let open ChainState cs; open Block b; open BHeader bheader
          open BHBody bhbody; open NewEpochState nes; open EpochState epochState
      in

        let  nes₁  = record newEpochState { epochState = record (EpochStateOf cs) {ls = ls₁} }
         cs'   = record cs
                   { newEpochState  = record nes { bcur = bcur'; epochState = record (EpochStateOf nes) {ls = ls'} }
                   ; lastApplied    = just $\begin{pmatrix} \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1792}{\htmlId{11338}{\htmlClass{Function}{\text{slot}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#2467}{\htmlId{11345}{\htmlClass{Function}{\text{bHeaderHash}}}}\, \\ \,\href{Ledger.Dijkstra.Specification.BlockBody.html#1864}{\htmlId{11359}{\htmlClass{Function}{\text{announcedEB}}}}\, \end{pmatrix}$
                   }
    in
    ∙ certifyEnv cs slot ⊢ LedgerStateOf cs ⇀⦇ (ebCert , reb) ,CERTIFY⦈ ls₁
    ∙ tt ⊢ nes₁ ⇀⦇ slot ,TICK⦈ nes
    ∙ (es , acnt) ⊢ (ls , bcur) ⇀⦇ b ,BBODY⦈ (ls' , bcur')
      ────────────────────────────────
      _ ⊢ cs ⇀⦇ (b , reb) ,CHAIN⦈ cs'

    The resulting chain state records the block as the last applied block, with its announcement, if any, pending for its successor.
